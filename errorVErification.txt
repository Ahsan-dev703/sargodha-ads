Error occurs in:
- backend/src/services/auth.service.js
- backend/src/services/email.service.js
- frontend/src/services/auth.service.js

Why it fails every time:
The verification token is generated in backend/src/services/auth.service.js, hashed, and stored in the user record. Then the verification link is generated in backend/src/services/email.service.js using the raw token and sent to the frontend. The actual validation in backend/src/services/auth.service.js does: hashToken(token) and compares it with emailVerificationTokenHash.
If the token is modified, URL is wrong, decoded/encoded incorrectly, expired, or the saved token does not match the link being clicked, the lookup fails and the app throws "Invalid or expired verification token" every time.

Solution:
1. Make sure the same raw token value is stored and later used for comparison.
2. Never compare a different token format or a URL-decoded version if the original token was not stored that way.
3. In registration, keep the raw token in the email link and store only the hash in the database.
4. In verification, do:
   const tokenHash = hashToken(token);
   const user = await User.findOne({ emailVerificationTokenHash: tokenHash, emailVerificationTokenExpiresAt: { $gt: new Date() } });
5. Confirm the API route is correct: /auth/verify-email/:token
6. Confirm the frontend request matches the backend route and that the token is not being double-encoded or stripped.
7. Check that the email template uses the correct verification URL and that CLIENT_URL is set correctly.
8. Make sure the database user record actually contains the token hash and expiration date.
9. Clear old invalid tokens and test with a fresh user registration after fixing the flow.
10. If email sending fails, also verify EMAIL_HOST, EMAIL_PORT, EMAIL_USER, EMAIL_PASSWORD, EMAIL_FROM, and CLIENT_URL in the backend .env file.
